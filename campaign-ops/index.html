One door for every change

Google's official Google Ads MCP server can only read. Reading is the easy part. Campaign Ops adds safe writing: the controls a careful media buyer would insist on, enforced in code.

No self-approval

The agent has 13 tools and none of them approves. Only a person can, in the console or an approval prompt in the chat app.

Fair Housing built in

Copy like "adults only" is blocked. Negative keywords that would hide ads from protected groups are always refused.

Budget limits

Step limits per change, a per-campaign range and an account-wide daily cap.

Dry run

Every proposal is validated by the platform without being applied, the way the Google Ads API's validate_only works.

Drift detection

If someone changed the live value after the proposal, nothing is overwritten. It becomes a conflict instead.

Approval binding

An approval is tied to a hash of the exact change. Editing the stored proposal afterwards is detected.

Collateral and brand checks

Negatives that would block converting searches or your own community name are flagged or blocked.

Kill switch and rate limits

One click pauses every change. Cooldowns and hourly caps stop runaway loops.

Tamper-evident audit

Every event is hash-chained. Editing any line breaks the chain, and the tool reports where.

Same code, three places

The guardrail engine is one TypeScript codebase. It runs as an MCP server for Claude Desktop, on this page as a browser build, and next against a real Google Ads test account through the official API.

Protocol
Model Context Protocol, stdio server, tool annotations, elicitation for in-chat approval
Engine
TypeScript, file-locked state, approval binding hashes, hash-chained audit log
Tests
28 automated tests: guardrails, lifecycle, console security, MCP over stdio
Security
Local console with key auth, Host header and origin checks, strict CSP, escaped AI text
